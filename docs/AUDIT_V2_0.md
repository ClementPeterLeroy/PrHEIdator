# Preliminary audit and modernization decisions

The audit used the files present when the development task began. No Git
repository was present. The read-only inspection preceded implementation.
All source and asset files were retained; the original scripts are text
snapshots in docs/legacy/, with migration hashes in ASSET_MIGRATION.json.

## Inventory

- Three Python scripts: PrHEIdator_Pong.py (approximately 2,260 lines),
  threadPong.py and parsing.py.
- 32 audio files: 22 WAV, 9 MP3 and 1 FLAC.
- 16 image files: 8 PNG and 8 JPEG.
- Two font files: WRESTLEMANIA.ttf at root and under src/font/. Both are
  preserved, including the redundant root copy under px/fonts/legacy/.
- Games_files/ contains a separate set of backgrounds, logos and sounds,
  including retired audio variants. No present Python script uses them.
- .venv_pong/ is a pre-existing local environment; .vscode/ is local IDE
  configuration and __pycache__/ contains generated bytecode.
- Pong_v1.py is mentioned by the IDE and earlier conversation but absent
  from disk at the start of this task. It has not been recreated or claimed
  as archived. No mobile source, static data directory or license was found.

Original imports: Pygame, NumPy, Flask and kafka-python, plus Python's
pathlib, sys, random, math, json, threading, os and re modules. Only Pygame
is needed in the modern application.

## Mode availability established from code and short runtime checks

Each of the five gameplay loops below was entered directly for 15 frames
with dummy SDL drivers and synthetic no-op events. That establishes that
the loops can execute, not that the old menus, balance or whole matches work.

| Feature | Original finding | v2.0 decision |
| --- | --- | --- |
| AI | Reactive right paddle; randomized detection zone; no learning | Preserve reactive opponent |
| Wall | Right-wall returns score; left miss calls a broken game-over timer | Preserve distinct survival mode; repair ending |
| Two-player Classic | Implemented collision zones, scoring to five | Preserve and share logic |
| Poder | Implemented centre-hit charge and close-range horizontal attacks | Preserve both players' mechanics |
| Four-player Classic | Four paddles; points awarded to last touch on any exit | Preserve unusual last-touch rule |
| Fun | Listed in selection array; no gameplay loop or launch action | Visibly disable |
| DeepIA | Checkbox only; turning it on bypasses reactive bot movement | Visibly disable; no neural implementation |
| Credit & Quit | Drawn but never selected or handled | Connect to a small credits/quit screen in existing style |

## Defects and dead code

- Intro originally requested generique.wav although generique.mp3 exists;
  three submenu branches requested Menu.mp3 although Menu.wav exists. The
  preceding troubleshooting session fixed these before this snapshot.
- Asset paths were relative to cwd; the preceding fix resolved that for the
  school game. v2.0 centralizes this behavior after relocation.
- Menus inspect `event` outside the event loop, repeating stale input or
  referencing unassigned data. Mouse targets are sometimes created only
  after input handling, allowing undefined rectangles on an early click.
- Controller blocks reference undefined `listK`, `listP` and `pos` and hide
  failures with bare `except`. They duplicate local input and no longer have
  a working integration with the main game.
- `Game2pFun`, the general `GameOver` flag and several animation helpers are
  unused; branch-local function definitions are repeated across modes.
- `DeepIA=True` makes the AI's only update branch unreachable.
- One shared mixer-busy check includes effects when deciding whether to
  restart music. Menu images and some audio are repeatedly loaded in loops.
- Game-over logic is duplicated, can continue simulation/scoring and often
  increments time only while a particular call path remains active. Wall
  mode calls it only on a miss and resets the ball immediately, so the return
  timer ordinarily fails to finish.
- Signed velocity comparisons differ between left and right paddles;
  bounds checks permit overshoot. Collisions use the previously drawn ball
  rectangle and do not consistently require motion toward the paddle.
- Blocking 150 ms flashes suspend event handling; debug output prints menu
  choices, AI samples and game-over counters repeatedly.

## Obsolete infrastructure

threadPong.py defines Flask registration routes, shared controller lists,
background threads and a Kafka consumer pointed at an external broker.
It is not imported by the school game. No connection to that broker was
attempted during this task. parsing.py serves the registration code and a
missing static/ data directory; it is not needed for local gameplay. Both
scripts are archived as text rather than left executable in the application.
No network/service dependencies or external controller blocks remain in src/.
Historical references remain only in the archival material and documentation.

## Gameplay corrections

These are intentional differences from buggy code, not a claim of frame-perfect
equivalence. Default rules, starting positions, ball radius, paddle dimensions,
colour scheme, score target, charge rules and base speeds remain recognizable.

1. All original pixels-per-frame velocities become pixels-per-second values
   at the original 100 Hz. Movement stays consistent when rendering varies.
   Excess stalled-frame time above 100 ms is discarded rather than teleporting.
2. Paddle bounces require an approach and separate the ball from the paddle.
   Top/bottom bounces clamp the ball radius inside the field. This prevents
   repeated overlap flips and changes boundary contact by up to five pixels.
   Goal scoring still uses the ball centre leaving the field.
3. Three-zone responses use symmetric bounded horizontal speed magnitudes
   on both vertical paddles: edge hits accelerate toward 5 px/step, centre
   hits slow speeds above 2 px/step, vertical changes are bounded at 10 px/step.
   A 10 px/step Poder shot remains fast until a centre hit reduces it. This
   repairs signed comparisons that accidentally favoured one side; balance
   should be reviewed by human playtesting.
4. Paddles clamp to the legal field on every update. Four-player paddles use
   a consistent 20 px corner margin instead of the inconsistent original
   end values. Initial coordinates are preserved until the first update.
5. Wall mode ends immediately after the first left miss and returns after
   the normal 2.8-second game-over interval. It retains unbounded scoring
   on right-wall hits rather than adding a new five-point target.
6. Finished matches stop accepting simulation/attacks, and the game-over
   timer advances every frame. Losing paddle fall is now presentation only.
7. Flashes retain the 150 ms pause without blocking event handling; display
   redraws current state rather than retaining stale geometry for a frame.
8. AI detection uses an exact normal CDF instead of 2,000 trapezoid samples,
   preserving the effective historical argument order (mu=.1, sigma=.4),
   random sampling, rounding and cap. Tracking speed stays 4 px/step and
   approaches the target without jittering past it.
9. Poder tests current ball/paddle positions rather than stale draw rectangles;
   a successful attack consumes charge and separates the shot from the paddle.

Esc navigation, intro skip, M mute and actionable credits/quit improve lifecycle
and local use. They add no new gameplay mode. No new graphical/audio assets,
engine, neural AI or online multiplayer were introduced.
